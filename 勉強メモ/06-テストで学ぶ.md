## 2. 単体テスト — tests/unit/

### 2.1 auth.test.ts

```typescript
describe('getSafeRedirectPath', () => {
  it.each(['/', '/search', '/post/abc?tab=1'])('同一オリジンの %s は通す', ...);
  it.each(['//evil.example', 'https://evil.example'])('危険なパスは fallback', ...);
});
```

**学び:** セキュリティ関数は **表形式テスト（it.each）** で拒否パターンを列挙。

### 2.2 validation.test.ts

- `javascript:` URL が弾かれる
- `//` 始まりアバターが弾かれる
- title 101 文字が弾かれる
- `getSafeHttpUrl` の境界

**やってみよう:** 新しい Zod スキーマを足したら、必ず **拒否ケース1つ以上** を追加。

## 3. RLS 結合テスト — tests/integration/rls.test.ts

### 3.1 セットアップ

**ファイル:** `tests/integration/setup.ts`

- テスト用 Supabase に接続（`.env.local`）
- ユーザー A / B / admin を作成
- 各ユーザー用の Supabase クライアント（別 JWT）

### 3.2 典型テストケース

| テスト | 期待 |
|---|---|
| ユーザー A が自分の post を update | 成功 |
| ユーザー A が B の post を update | 失敗 |
| 一般ユーザーが category insert | 失敗 |
| admin が category insert | 成功 |
| ユーザー A が B の comment を delete | 失敗 |

### 3.3 実行

```bash
# Supabase ローカル起動が必要
npm run supabase:start
npm run test:integration
```

**CI:** `.github/workflows/ci.yml` で自動実行。

## 4. E2E — tests/e2e/

### 4.1 auth.spec.ts

- 未ログイン → `/create` → `/login?redirect=...`
- ログイン後 redirect 先へ戻る
- 一般ユーザー → `/admin` → トップへ
- `//evil.com` redirect が拒否される

### 4.2 post-crud.spec.ts

- 投稿作成 → 編集 → 削除
- **他人の投稿に編集・削除ボタンが出ない**
- 週1制限（同カテゴリ2回目が失敗）

E2E は **UI レベル** の確認。RLS の代わりにはならないが、ユーザー体験として重要。
