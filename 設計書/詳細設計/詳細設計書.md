## 1. システム構成

### 1.1. 全体像

Web のみ（Next.js App Router）。ネイティブアプリは対象外。スマホ幅のブラウザは必須。

```
Browser
  │  Cookie（Supabase Auth セッション）
  ▼
Next.js（app/ + middleware）
  ├─ Server Component（トップ ISR など）── getPublicRepository()
  ├─ Client Component（大半の画面）──── getRepository() / useXxx
  └─ Route Handler
        ├─ GET  /auth/callback          OAuth code → session
        └─ POST /api/account/delete     退会（service_role）
              │
              ▼
         Supabase
           ├─ Auth（email / Google / パスワードリセット）
           ├─ PostgREST + RLS（データの正本）
           └─ PostgreSQL（schema.sql + migrations）
```

データの書き込みは原則 **ブラウザ → `@supabase/supabase-js` → RLS**。画面は Supabase を直接叩かず `DataRepository` を通す。例外は退会だけ（`SUPABASE_SERVICE_ROLE_KEY` はサーバー専用）。

### 1.2. 実行環境

接続先は `.env.local` の `NEXT_PUBLIC_SUPABASE_URL`。URL を見て Docker（ローカル Supabase）か Cloud かをバッジ表示する。詳細は [`環境構成.md`](../環境/環境構成.md)。

| 層 | 役割 |
| --- | --- |
| 画面 | ボタンの出し分け。壊されてもよい |
| Repository + Zod | 型・文字数・URL の整形。権限の正本ではない |
| RLS / トリガー | 拒否の正本。なりすまし・いいね数改ざん・週1回避を止める |

### 1.3. プロセス内の枠（layout）

```
QueryProvider
  LocaleProvider（現状 ja 固定）
    AuthProvider → SupabaseAuthProvider
      Navbar
      <main> 各 page
      Footer
```

`middleware.ts` は全ページ（静的アセット以外）でセッション Cookie を更新し、保護パスを跳ねる。

### 1.4. 主要環境変数

| 変数 | 使う場所 |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | ブラウザ・サーバー共通 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 同上。RLS が効くキー |
| `SUPABASE_SERVICE_ROLE_KEY` | `lib/supabase/admin.ts` のみ。退会 |

## 2. モジュール設計

### 2.1. ディレクトリ責務

| 場所 | 責務 |
| --- | --- |
| `app/` | URL の入口。権限の薄いチェック、データの受け渡し |
| `components/` | 見た目と画面内インタラクション |
| `lib/data/` | `DataRepository`。Supabase 行 ↔ アプリ型 |
| `lib/auth/` | ロール判定、安全なリダイレクト、退会フレーズ |
| `lib/supabase/` | クライアント生成（browser / server / public / admin / middleware） |
| `lib/validation/` | Zod。アプリ層の入力チェック |
| `lib/search.ts` `lib/ranking.ts` `lib/post-frequency.ts` | ドメイン計算（DB に出す前の UX / クライアントフィルタ） |
| `lib/legal/` | 規約・プライバシー・クレジット本文 |
| `lib/i18n/` `messages/` | 文言 |
| `types/index.ts` | ドメイン型 |
| `supabase/` | `schema.sql`・migrations・seed |

### 2.2. データアクセスの分岐

| 入口 | ファイル | クライアント | 用途 |
| --- | --- | --- | --- |
| `getRepository()` | `lib/data/index.ts` | ブラウザ `createClient()` | 画面の CRUD |
| `getServerRepository()` | `lib/data/server.ts` | Cookie 付き server client | ログイン状態が要るサーバー処理（現状ほぼ未使用） |
| `getPublicRepository()` | 同上 | Cookie なし `createPublicClient()` | トップ ISR。全員同じ HTML |
| hooks `usePosts` など | `lib/data/hooks.ts` | `getRepository()` + TanStack Query | クライアント画面 |

`SupabaseDataRepository` はコンストラクタで `() => SupabaseClient` を受け取る。サーバーとブラウザで同じクラス。

### 2.3. 認証モジュール

| ファイル | 役割 |
| --- | --- |
| `AuthProvider` | 画面向けファサード。`useAuth()` |
| `SupabaseAuthProvider` | `getSession` / `onAuthStateChange`、`profiles` 取得、signIn / signUp / OAuth / reset |
| `lib/auth/roles.ts` | `isAdminRole` |
| `lib/auth/public-board.ts` | 掲示板モードのスイッチ。true のあいだログイン導線を隠す |
| `lib/auth/safe-redirect.ts` | `getSafeRedirectPath`。`//` や外部 URL を拒否 |
| `lib/auth/account.ts` | メール identity 判定、退会フレーズ `退会する` |
| `lib/supabase/middleware.ts` | 保護パスと admin ゲート |

保護パスは API 仕様書 2.2 と同じ。`/create` は掲示板モードでは保護しない。`/admin` は `profiles.role === 'admin'` でなければ `/?error=forbidden`。

### 2.4. 画面モジュール（ページ → 本体）

| URL | page | 本体 |
| --- | --- | --- |
| `/` | `app/page.tsx`（Server） | `HomePageClient` |
| `/search` | `app/search/page.tsx` | 同ファイル（`Suspense` + inner） |
| `/ranking` | `app/ranking/page.tsx` | 同ファイル |
| `/create` | `app/create/page.tsx` | `PostForm` |
| `/post/[id]` | `app/post/[id]/page.tsx` | `PostDetail` + `CommentSection` |
| `/post/[id]/edit` | `app/post/[id]/edit/page.tsx` | `PostForm` + `initialPost` |
| `/bookmarks` | `app/bookmarks/page.tsx` | `PostCard` グリッド |
| `/profile/[userId]` | `app/profile/[userId]/page.tsx` | 同ファイル |
| `/profile/edit` | `app/profile/edit/page.tsx` | 同ファイル + `DeleteAccountSection` |
| `/settings` | `app/settings/page.tsx` | リダイレクトのみ |
| `/login` `/signup` `/forgot-password` `/reset-password` | 各 page | 各 `*Form` |
| `/admin` | `app/admin/page.tsx` | カテゴリ UI + `AdminModeration` |
| `/terms` `/privacy` `/credits` | 各 page（Server） | `LegalPageShell` |

### 2.5. キャッシュ方針（TanStack Query）

`QueryProvider` デフォルト: `staleTime` 5分、`gcTime` 30分、フォーカス再取得なし、retry 1。

| キー | 特記 |
| --- | --- |
| `majorCategories` `subCategories` `tags` | `staleTime: Infinity`（マスタ） |
| `posts` / `post` / `postsByUser` | viewerUserId をキーに含む（非表示除外） |
| 更新後 | `useInvalidate()` で関連キーを無効化 |

トップだけ ISR。検索・詳細はクライアント取得。

### 2.6. i18n

- 正本: `messages/ja.ts`。`en.ts` は同じキー構造。
- 画面: `useTranslations().t('nav.search')`。
- サーバー（metadata・法務）: `getMessages(DEFAULT_LOCALE)`。
- 現状 `LocaleProvider` は layout で `ja` 固定。`profiles.locale` 列は将来用。

## 3. クラス設計

TypeScript の interface / type が「クラス」に相当する。実行時の実装クラスは `SupabaseDataRepository` が中心。

### 3.1. ドメイン型（`types/index.ts`）

| 型 | 要点 |
| --- | --- |
| `User` | id, name, avatarUrl |
| `Profile` | User + email?, role (`user` \| `admin`), createdAt |
| `Post` | ジャンル、tagIds、title / description / url、likeCount、createdAt、埋め込み user |
| `Comment` | body、埋め込み user |
| `Like` `Bookmark` `HiddenPost` | ユーザー×投稿 |
| `Report` | reason 4種、status pending/resolved |
| `MajorCategory` `SubCategory` `Tag` | マスタ。order / isActive |
| `PostFrequencyCheck` | canPost, nextAvailableAt, daysRemaining |
| `PostRankingEntry` `UserRankingEntry` | rank + 対象 + 値 |
| `RankingPeriod` | `all` \| `month` \| `week` |

DB の snake_case は repository が camelCase に変換する。画面は DB 列名を知らない。

### 3.2. `DataRepository`（`lib/data/types.ts`）

画面が呼んでよい操作の一覧。メソッド表は API 仕様書 4.1 と同一。追加する機能は **まずこの interface**、次に `SupabaseDataRepository`、必要なら hook。

入力型:

- `CreatePostInput` / `UpdatePostInput`
- `PostRankingOptions` / `UserRankingOptions`
- `HomePageData`（recent / popular / ranking / heroCandidates / stats / マスタ）

### 3.3. `SupabaseDataRepository`

| 責務 | 内容 |
| --- | --- |
| 検証 | `lib/validation/data.ts` の Zod。失敗は throw |
| 身元 | 書き込みで渡された userId と `auth.getUser()` を照合（`assertActingAs`）。掲示板モードでは userId なし（匿名）を許可 |
| 変換 | `supabase-posts.ts` / `supabase-comments.ts` の mapper |
| 週1 UX | クライアント側 `lib/post-frequency.ts`。DB トリガーが本命 |
| タグ同期 | `post_tags` を delete + insert |
| ランキング | 全期間は `like_count` ソート。週/月は likes の created_at 集計 |

関連ファイル:

- `lib/data/supabase-posts.ts` … `POST_SELECT` と `mapSupabasePost`
- `lib/data/supabase-comments.ts` … コメント同様

### 3.4. 認証コンテキスト（`lib/auth/types.ts`）

```
AuthContextValue
  user: { id, email? } | null
  profile: Profile | null
  loading
  signOut()
  refreshProfile()
```

`SupabaseAuthProvider` がこれに signIn / signUp / OAuth / パスワードリセットを足す。画面は `useAuth()` だけ見る。

### 3.5. バリデーション（`lib/validation/data.ts`）

| 対象 | ルール（抜粋） |
| --- | --- |
| 投稿タイトル | 1〜100 |
| 投稿本文 | 1〜1000 |
| URL | http/https のみ。表示は `getSafeHttpUrl` |
| コメント | 1〜1000 |
| 通報理由 | 4値の union |
| タグ | 最大20 |
| アバター | 安全な相対パス or http(s) |
| ID | UUID（ユーザー・投稿） |

### 3.6. アバター（`lib/avatars/index.ts`）

`UserAvatar` は `avatarUrl` が画像として安全ならそれを出し、なければ `getAvatarPathForUserId` で `public/avatars/NNN.svg` を安定選択。生成は `npm run avatars:generate`。ライセンスは `/credits`。

## 4. データフロー

### 4.1. トップ（ISR）

```
GET /
  app/page.tsx（revalidate=300）
    getPublicRepository().getHomePageData()
      anon client（Cookie なし）
        posts / likes 集計 / categories
    HomePageClient に props
      マウント後に hero をランダム抽選
```

全員同じ HTML。閲覧者の `hidden_posts` は見ない。開発時 `nextHomeFetchCount()` で再生成回数を画面に出す。

### 4.2. 一覧・詳細（クライアント）

```
page マウント
  useAuth() で user.id
  usePosts(userId) / usePost(id, userId) / ...
    getRepository().getXxx(viewerUserId)
      hidden_posts を見て除外
  操作（いいね等）
    repository mutation
    useInvalidate('posts', 'post', ...)
```

検索は **全件取得 → `filterAndSortPosts`**。件数増えたらサーバーフィルタに切り替える前提。現状はクライアント完結。

### 4.3. 投稿作成

```
PostForm.submit
  掲示板モードでは未ログインのまま進む（user_id は NULL）
  ログイン中だけ checkPostFrequency（UX）
  createPost（Zod + assertCanWriteAs + insert + tag 同期）
    DB BEFORE INSERT: enforce_post_frequency
      user_id が NULL なら週1を見ない
      それ以外は advisory lock → 直近7日の同一 user×major があれば 23514
      created_at を now() に固定
  invalidate → / へ
```

編集は週1を見ない。`user_id` / `like_count` / `created_at` は本人でも UPDATE 不可（不変トリガー）。

### 4.4. いいね・コメント・ブックマーク

```
LikeButton
  addLike / removeLike
    likes 行の INSERT/DELETE
    トリガーが posts.like_count を増減
コメント
  addComment / updateComment / deleteComment
  削除は本人 or admin（RLS）
ブックマーク
  SELECT も本人の行だけ（他人に見えない）
```

### 4.5. 認証

**メールログイン**

```
LoginForm → signInWithPassword → Cookie セッション
  redirect = getSafeRedirectPath(?redirect)
```

**Google**

```
GoogleSignInButton → signInWithOAuth
  Supabase 認可画面
  GET /auth/callback?code=&next=
    exchangeCodeForSession
    失敗 → /login?error=auth_callback
```

新規 Auth ユーザー → `on_auth_user_created` で `profiles` 1行。

**パスワードリセット**

```
/forgot-password → resetPasswordForEmail（redirect /reset-password）
  メールリンク → セッション
  /reset-password → updateUser({ password })
  /login?reset=success
```

### 4.6. 退会

[`退会処理設計.md`](./退会処理設計.md) のシーケンスどおり。UI の実体は `/profile/edit#delete-account`。`/settings` は転送。

`auth.admin.deleteUser` → `profiles` CASCADE → 投稿・いいね・コメント・ブックマーク・通報・非表示も削除。

### 4.7. ランキング

| タブ | 計算 |
| --- | --- |
| 投稿・全期間 | `posts.like_count` DESC |
| 投稿・週/月 | 期間内 likes を post_id 集計 |
| ジャンル | 上記 + `major_category_id` |
| ユーザー・likes | その人の投稿が期間内に受け取った likes |
| ユーザー・posts | 期間内の投稿数 |

期間の「今月」「今週」はカレンダー月/週ではなく、**今から 30 日 / 7 日**（`lib/ranking.ts` の `getPeriodStart`）。

### 4.8. モデレーション

```
通報: reportPost upsert（post_id + reporter_id）
非表示: hidden_posts INSERT。getPosts 系が viewer 指定時に除外
admin: getReports → deletePosts + resolveReports
```

admin は他人の投稿**本文を編集しない**。削除と通報解決のみ。

### 4.9. 週1制限の二重化

| 層 | 役割 |
| --- | --- |
| `lib/post-frequency.ts` | 日数表示。テストあり |
| repository `checkPostFrequency` | フォーム送信前 |
| `enforce_post_frequency` トリガー | 同時投稿・過去日時指定を含む強制。migration `20260822120000_security_constraints.sql` |

クライアントを迂回しても DB が拒否する。

## 5. セキュリティ（設計上の約束）

| 項目 | 方針 |
| --- | --- |
| service_role | クライアント・`NEXT_PUBLIC_*` に出さない |
| CSRF | Cookie SameSite + 退会 POST はセッション必須。独自 POST を増やすときは [`セキュリティ運用設定.md`](../セキュリティ運用設定.md) |
| リダイレクト | `getSafeRedirectPath` |
| XSS | 投稿 URL は http(s) のみ。文言は React テキストノード |
| IDOR | repository の acting user 照合 + RLS |
| role 昇格 | トリガーで `profiles.role` 不変。SQL Editor のみ |
