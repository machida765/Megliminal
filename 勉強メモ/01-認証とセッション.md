# 01. 認証とセッション — ソース解説

## 1. 認証の全体フロー

Megliminal の認証は **Supabase Auth** が本体。アプリは以下を担当するだけ:

1. ログインフォーム / OAuth ボタン
2. セッション Cookie の refresh（middleware）
3. プロフィール（`profiles`）の読み取り

パスワードの **ハッシュ化・保存** は `auth.users` テーブル（Supabase 管理）に任せる。

---

## 2. パスワードはどこにある？

| テーブル | パスワード |
|---|---|
| `auth.users` | ✅ `encrypted_password`（bcrypt ハッシュ） |
| `public.profiles` | ❌ なし（表示名・アバター・role のみ） |

アプリコードは平文パスワードを **保存しない**。`signUp` / `signInWithPassword` で Supabase に渡すだけ。

---

## 3. SupabaseAuthProvider — クライアント側の中心

**ファイル:** `components/providers/SupabaseAuthProvider.tsx`

### 3.1 セッション初期化

```typescript
const { data: { user: currentUser } } = await supabase.auth.getUser();
```

- `getSession()` より **`getUser()`** を使う（Supabase SSR 推奨）
- JWT をサーバー側で検証した結果が返る

### 3.2 onAuthStateChange

ログイン・ログアウト・トークン更新のたびに `user` / `profile` を更新。

### 3.3 パスワードリセット

```typescript
await supabase.auth.resetPasswordForEmail(email, {
  redirectTo: `${origin}/auth/callback?next=/reset-password`,
});
```

フロー:

```
/forgot-password でメール送信
  → メール内リンク
  → /auth/callback?code=...&next=/reset-password
  → exchangeCodeForSession
  → /reset-password で updateUser({ password })
```

### 3.4 全端末ログアウト

```typescript
await supabase.auth.signOut({ scope: 'global' });
```

`scope: 'global'` で **refresh token を全端末失効**。盗まれたセッション対策の基本。

## 4. OAuth コールバック — Open Redirect 対策

**ファイル:** `app/auth/callback/route.ts`

```typescript
const next = searchParams.get('next') ?? '/';
const { error } = await supabase.auth.exchangeCodeForSession(code);
if (!error) {
  const safeNext = getSafeRedirectPath(next);
  return NextResponse.redirect(`${origin}${safeNext}`);
}
```

### getSafeRedirectPath の中身

**ファイル:** `lib/auth/safe-redirect.ts`

```typescript
if (
  !value ||
  !value.startsWith('/') ||
  value.startsWith('//') ||      // ← ここが重要
  value.includes('\\') ||
  /[\u0000-\u001f\u007f]/.test(value)
) {
  return fallback;
}
```

#### なぜ `//evil.com` が危険？

ブラウザは `//evil.com` を **スキーム相対 URL** と解釈し、現在のプロトコル（https:）で evil.com へ飛ぶ。

`/evil.com` だけチェックしても `//evil.com` は通ってしまう → **Open Redirect** の定番パターン。

## 5. middleware — セッション refresh

**ファイル:** `lib/supabase/middleware.ts`（`middleware.ts` から呼ばれる）

```typescript
const { data: { user } } = await supabase.auth.getUser();
```

毎リクエストで:

1. Cookie からセッション読み取り
2. 必要なら refresh token で更新
3. 更新された Cookie をレスポンスにセット

**ログイン必須パス:**

```typescript
const loginRequiredPaths = [
  '/create', '/profile/edit', '/settings',
  '/bookmarks', '/reset-password'
];
const isEditPost = /^\/post\/[^/]+\/edit/.test(pathname);
```

未ログインなら `/login?redirect=元のURL` へ。

## 6. セッション / トークンの寿命（運用）

**ファイル:** `設計書/セキュリティ運用設定.md`

| 設定 | 推奨値 |
|---|---|
| JWT expiry | 3600 秒（1時間） |
| Refresh token rotation | 有効 |
| Refresh token reuse interval | 10 秒 |

コードではなく **Supabase Dashboard** で設定。本番リリース前に人間が確認する項目。
