# セキュリティ運用設定

コードだけでは強制できない本番環境の設定値をまとめる。

## Supabase Auth

- JWT expiry: 3600 秒（1時間）
- Refresh token rotation: 有効
- Refresh token reuse interval: 10 秒
- メール認証: 本番では有効
- ログイン試行の rate limit: Supabase Dashboard の既定値以上に緩和しない
- CAPTCHA: 不正ログインやサインアップが観測された時点で有効化
- アプリのログアウト: `scope: global` とし、全端末の refresh token を失効

設定場所は Supabase Dashboard の **Authentication > Settings / Rate Limits**。

## HTTPS

- 本番は HTTPS へ常時リダイレクトするホスティングを使用
- `Strict-Transport-Security` は本番レスポンスのみ送信
- カスタムドメイン設定後、HTTP、サブドメイン、証明書更新を確認

## CSRF

現在、状態を変更する独自 API Route / Server Action はない。書き込みは Supabase の
アクセストークンと RLS で保護する。今後 Cookie 認証の独自エンドポイントを追加する場合は、
同一オリジン検証と CSRF トークン検証を必須とする。

## リリース時の確認

```text
[ ] Supabase Auth の JWT / refresh token 設定が上記どおり
[ ] Auth rate limit が有効
[ ] 本番 URL で HTTP から HTTPS へリダイレクトされる
[ ] HSTS / CSP / nosniff / frame 拒否ヘッダーが返る
[ ] NEXT_PUBLIC_SUPABASE_ANON_KEY に secret/service_role key を使用していない
[ ] npm run audit が成功する
```
