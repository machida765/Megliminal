# 環境・構成

いまの Megliminal が何の上で動いているか、設定の切り替え方です。画面の地図は `ソース案内.md`、フォルダは `ファイル構成.md`、データ切替の意図は `データソース切り替え.md`。トップのキャッシュがどの箱で動くかは `トップキャッシュと置き場所.md`。

**いまの作業コピー（`.env.local`）は Docker 上のローカル Supabase です。** クラウドのプロジェクトも残してあり、コメントを入れ替えれば戻せる。

---

## 全体像

```
ブラウザ
    │  http://localhost:3000
    ▼
Next.js アプリ（このリポジトリ）
    │
    └─ Supabase
           ├─ URL が 127.0.0.1 / localhost  → Docker のローカル Supabase
           └─ URL が https://….supabase.co  → ネット上の Supabase クラウド
```

ナビ左のバッジが **Docker** / **Cloud** のどれかを示す（本番の Cloud では非表示）。判定は `lib/config/data-source.ts`。

## アプリ側のスタック

| 層 | 中身 |
|---|---|
| OS（開発） | Windows |
| 言語 | TypeScript |
| フレームワーク | Next.js 16（App Router） / React 19 |
| UI | Tailwind CSS 4、shadcn（base-nova）、lucide |
| データ取得 | `DataRepository` + `lib/data/hooks.ts`（一部 TanStack Query） |
| 認証 | Supabase Auth（メール・Google） |
| 文言 | `messages/ja.ts` が正本。デフォルト言語は `ja` |
| 本番ホスト | 未固定（Vercel 等へのデプロイ設定はリポジトリにない） |

起動:

```bash
npm run dev
```

通常は `http://localhost:3000`。`next.config.ts` に特別な設定はほぼ無い。

## データの2モード

切り替えは `.env.local`。変更後は **開発サーバーの再起動** が必要。雛形は `.env.local.example`。実ファイルは Git に入れない。

### 1. Docker（PC 上の Supabase）← いまの `.env.local`

```env
NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321
NEXT_PUBLIC_SUPABASE_ANON_KEY=（npm run supabase:status の anon key）
```

事前に [Docker Desktop](https://www.docker.com/products/docker-desktop/) を起動してから:

```bash
npm run supabase:start
npm run supabase:status
npm run dev
```

止めるとき: `npm run supabase:stop`  
**コマンドの詳細・トラブルシュート**: `環境/Docker起動停止.md`

ローカル Supabase の主なポート（`supabase/config.toml`）:

| 用途 | ポート |
|---|---|
| API / Auth（アプリが繋ぐ URL） | 54321 |
| Postgres | 54322 |
| Studio（管理画面） | 54323 付近（status で確認） |

スキーマは `supabase/migrations/` と `supabase/schema.sql`。開発シードは `supabase/seed-dev.sql`。

### 2. Cloud（ネット上の Supabase）

```env
NEXT_PUBLIC_SUPABASE_URL=https://（project-ref）.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=（ダッシュボードの anon / publishable key）
```

- Docker は不要。ネット接続が必要
- 認証・DB はクラウド側。Google ログインはクラウド側の設定が要る
- 手順の詳細は `Supabaseセットアップ手順.md`

`.env.local` では Docker 用とクラウド用をコメントで入れ替えて使う想定。

## 環境変数

アプリが読むのは次の2つ（すべて `NEXT_PUBLIC_` なのでブラウザからも見える）。

| 変数 | 意味 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | localhost なら Docker、`https://` なら Cloud |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 公開可能なキー。service_role は置かない |

判定の実装: `lib/config/data-source.ts`  
接続: `lib/supabase/client.ts`（ブラウザ） / `server.ts`（Cookie 付き） / `public.ts`（トップの ISR 用）

## まだこの構成に無いもの

- Cloudflare への移行はしない（認証・DB は Supabase のまま）
- CI / 本番デプロイの固定先
- `service_role` キーをアプリに置く構成（使わない）
